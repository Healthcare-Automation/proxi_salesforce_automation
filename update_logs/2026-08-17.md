## Parser: handle "City. ST" / "City ST" practice values (job create failure)

- **When:** 2026-08-17
- **Area:** `src/utils/job_content_parser.py` (`_parse_city_state`), `tests/test_job_content_parser.py`
- **What:**
  - Kimedics labeled a practice `1029 - Keizer. OR` (period instead of comma before the state). The parser only split on commas, so the row stored `city='Keizer. OR'`, `state=NULL`; the resolver skips worksite lookup/create without both city and state, so the Job__c create failed with `no_worksite_account_id` (run #3206, job 20306, events 7044–7046).
  - Fix: for numeric-prefix practice values with no comma, a trailing 2-letter token validated against `US_STATE_CODE_TO_NAME` (separated by `.` or whitespace) is now split off as the state. City-only values (`4190 - Gloucester`) and non-prefixed practice names are unchanged.
  - Two new tests (period variant end-to-end, space variant + guard cases); full parser suite 59/59.
- **Notes:** Job 20306 was created manually in Salesforce by the client — no backfill needed; the punctuation-stripping practice key (`1029 keizer or`) will link future emails to that record. Only one row in `job_current` ever had this pattern. Deployed to Modal (`salesforce-automation`) same day.
